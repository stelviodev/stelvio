REVIEWER GUIDE

Stelvio Traforo
Persistent bastions, transparent local sockets.

A self-contained interactive guide to the current architecture, implementation, alternatives, and validation gates. Source excerpts identify the code they describe.

The architecture

Two independent paths share a local handler. AppSync carries invocations and responses. Traforo carries database TCP; a Traforo DNS relay handles private DNS.

Invocation plane

Public Function URL → Lambda stub → AppSync Events WSS → local bridge → local handler → correlated result back

Database plane

Handler socket → macOS route/utun → root helper → Unix datagram carrier → nonroot Traforo forwarder → SOCKS5/OpenSSH → plugin SSM WSS → SSM agent → loopback sshd → DocumentDB

Private DNS plane

getaddrinfo → macOS scoped resolver → local Traforo DNS relay → SOCKS/SSH TCP → VPC resolver (+2)

Control plane

CLI → isolated Python networking child → per-VPC supervisors. A launchd root helper owns host mutations and journals. One selected Go+cgo executable serves two processes: helper and forwarder.

Only explicit bastions: False/omitted warns and runs without managed networking. True/config/dict creates a persistent bastion through deploy. Application deployment owns the bastion; tunnel sessions only connect to it.

Try admission

Host routing also affects other local processes targeting enabled CIDRs. There is one machine-wide helper lease. Overlapping enabled CIDRs and conflicting DNS ownership are rejected. General UDP, ICMP and IPv6 forwarding are outside this implementation.

Complexity from first principles
Each adapter follows a requirement. Removing a requirement can remove machinery; it also changes the contract.
Why sockets → packets → SOCKS → SSH → SSM?
The application creates normal sockets. Transparent host routing exposes IP packets at utun. OpenSSH dynamic forwarding consumes streams, so tun2socks translates packets back into TCP connections. SSH authenticates and opens dynamic remote sockets. SSM supplies the byte carrier without public SSH ingress. WSS is the AWS plugin’s data transport. The Unix carrier keeps raw utun authority inside the small privileged helper.
These are consequences of combining transparent clients, private DNS, no public SSH ingress, and a narrow root boundary. They are not all necessary for one manually configured database client.

Compared with ssh-over-ssm
ssh-over-ssm supplies SSH access over SSM and reduces inbound-port exposure. That transport idea corresponds to Stelvio’s OpenSSH/ProxyCommand/plugin/agent segment. It does not by itself supply transparent packet routing, scoped private DNS, topology discovery, readiness admission, or Stelvio’s helper ownership journal. Reusing a transport wrapper would therefore leave most host integration responsibilities.
ssh-over-ssm reference. This comparison concerns architectural scope; no unverified implementation details from that project are asserted.


Technical implementation
One GoReleaser configuration for local and CI builds
GoReleaser v2.18.3 owns architecture settings, cgo/minimum-macOS flags, artifact names and linker injection. CI uses a release tag. The developer script builds a nonpublishing snapshot with the pinned base and checkout commit, captures source/config changes, validates both images, and atomically publishes a bundle with build.json. The source fingerprint distinguishes uncommitted edits. Apple Silicon executes amd64 through Rosetta; Intel statically validates cross-built arm64 and records execution pending.
make -C pkg/traforo-client-go build
# Equivalent build without installation:
uv run python pkg/traforo-client-go/scripts/build.py --build-only
# Build plus normal authorized installation:
uv run python pkg/traforo-client-go/scripts/build.py
# Copy the exact export command printed by the script.
"$STLV_TRAFORO_DEV_BINARY" version
Both artifacts use CI release names: traforo-darwin-arm64 and traforo-darwin-amd64. Build-only never authorizes helper installation. Identical bytes additionally require identical source, build metadata, Go toolchain and SDK. These changes do not constitute a new AWS or privileged networking proof.
Contiguous source excerpts are embedded with explicitly scoped digests. The monorepo pkg/traforo-client-go source is authoritative for the Go client API and unit tests. It is mirrored to stelviodev/traforo, which owns release builds and Go implementation CI. Stelvio downloads pinned v0.0.7 executables into its private binary cache; wheel and sdist contain neither executables, developer scripts nor Go source. Ordinary installation never compiles. Developers can build both release architectures and install the host image with uv run python pkg/traforo-client-go/scripts/build.py, then run the exact export STLV_TRAFORO_DEV_BINARY=... command it prints before using stlv. There is no persistent developer marker; unset the variable and run stlv tunnel install to restore the pin. The helper and isolated forwarder use the captured selection, while release checksums and caches remain unchanged. Invalid overrides fail closed. GITHUB_TOKEN, if supplied by the environment, authenticates the GitHub API download; redirects drop credentials. Public downloads need no token. Production never invokes gh. The root helper and nonroot forwarder still run the same installed image, verified against the selected release or developer digest. Ordinary uninstall and forwarder startup do not download. What would be simpler?
SSM remote-host port forwarding
Smallest for one fixed endpoint: SDK/CLI StartSession plus AWS plugin. Lose transparent host routing and arbitrary member connections unless adding per-endpoint mappings and DNS. Running aws ssm start-session in a thread handles process lifetime, not DNS or crash-safe host ownership.
OpenSSH fixed -L forwards
Fewer moving pieces than TUN/SOCKS when endpoint count is fixed. Replica discovery and original TLS hostnames require careful local mappings. SSM can remain the carrier.
Direct SSH + Go SOCKS/TUN
Removes OpenSSH subprocess and AWS plugin/agent carrier if SSH is public. Similar to the pinned SST path. Trades fewer dependencies for public ingress and in-process SSH implementation.
Existing VPN / sshuttle
Can substantially reduce Stelvio code by delegating routing and DNS. Requires external installation, privileges, policy and cleanup guarantees; support shifts outside Stelvio. A managed VPN can also add recurring AWS cost.

AWS

Private DNS in Traforo
The nonroot Go forwarder owns one loopback UDP/TCP listener pair per VPC, DNS parsing, upstream TCP exchanges through SOCKS, and DNS payload probes. Python coordinates AWS/member discovery and proves OS resolver delivery through generation-bound observations. The helper owns resolver files, routes, devices, and cleanup.
Traforo reports one semantic version. Stelvio requires the pinned base version (v0.0.7); a v0.0.7-dev+g<commit> snapshot requires STLV_TRAFORO_DEV_BINARY. Validate the image before host changes and check the installed forwarder directly without downloading again.
# Optional: test local Go changes instead of the pinned release.
uv run python pkg/traforo-client-go/scripts/build.py
# Run the exact export command printed by the builder in each networking shell.
"$STLV_TRAFORO_DEV_BINARY" version
uv run stlv dev
Listener lifetime is independent of a packet attempt. During reconnect it keeps its port and replies SERVFAIL to owned queries; unowned names receive REFUSED. There is no relay cache. Bounded JSON request/reply control uses request IDs, unit generations, transport attempts, and DNS revisions to fence stale operations and responses.
Go limits DNS work to 32 concurrent requests, a 4096-byte UDP ceiling, 65535-byte messages, three-second I/O budgets, and eight queries per TCP connection. Readiness requires both upstream SOCKS probes and ordinary host TCP through utun, plus macOS scoped resolver observation.
Maintained regression tests
Go owns algorithm tests; Python owns orchestration and actual CLI, binary, and OS interoperability.
Which tests own the behavior?
Go tests exercise concurrent two-VPC megabyte streams, half-close, complete responses, framing, generations, DNS and journals. Python tests exercise real installed-binary, OS and CLI interoperability; pytest never compiles Go.
Explicit host mutation tier
uv run pytest tests/integration --integration-macos-privileged -n 0 -v
All host mutations require this flag. The fixture serializes across users, preserves the installed helper, audits host cleanup and restores the original image. It covers 100 cycles, owner/parent death, helper restart, foreign resolver protection and administration faults.
Separate AWS acceptance
STLV_TEST_AWS_PROFILE=default uv run pytest tests/integration \
  --integration-macos-privileged --integration-tunnel -n 0 -v
Tests verify TLS/member discovery/read-write, reconnect, partial failure, SSH key changes and standalone access. Normal exit retains bastions; proof application teardown removes them. run_all.sh never runs host-mutating tests.
